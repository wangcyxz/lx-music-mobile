# 新增功能说明（自定义源在线更新监控 / 音乐下载与边听边下 / 配置备份与恢复 / 本地音乐扫描播放）

> 当前基线：上游 v1.9.2（2026-10-30），定制版本号 1.9.2 / versionCode 79

本次改动在 lx-music-mobile（v1.9.1）基础上新增两个能力，均为纯 JS/TS 实现，不需要修改原生工程。

## 一、自定义源在线更新监控

### 使用方式

1. 设置 → 基本设置 → 自定义源 → 导入 → 在线导入，输入脚本地址。
2. 导入时会记录脚本地址（列表里会显示「在线源」标记）。
3. 打开自定义源弹窗后，底部新增「检查更新」按钮，可立即检查所有在线源。
4. 设置 → 基本设置 中新增两个开关：
   - **自动检查自定义源更新**（默认开启）：启动 8 秒后检查一次，之后每 30 分钟判断一次是否到达 6 小时检查周期。
   - **静默自动更新自定义源**（默认关闭）：发现新版本直接替换脚本，不弹窗；更新的是当前启用的源时会自动重新加载。

### 实现要点

| 文件 | 说明 |
| --- | --- |
| `src/core/userApiUpdate.ts` | 更新检查核心：抓取远端脚本、解析 `@version`、比较版本、提示/静默更新、热重载、启动监控 |
| `src/utils/data.ts` | `UserApiInfo` 增加 `sourceUrl / lastCheckTime / latestVersion / hasUpdate / checkError` 字段的持久化；新增 `updateUserApiScript`、`setUserApiUpdateState`、`parseUserApiScriptInfo` |
| `src/core/userApi.ts` | `importUserApi(script, sourceUrl)` 记录来源地址；新增 `refreshUserApiList` |
| `src/screens/.../UserApiEditModal` | 列表展示「可更新 {version}」、单项「立即更新」、在线源标记与检查失败原因；底部「检查更新」按钮 |
| `src/screens/.../Basic/UserApiUpdateSettings.tsx` | 两个自动更新开关 |

版本比较复用 `src/utils/index.ts` 的 `compareVer`，因此 `1.2.0`、`v1.2.0`、`1.2.0-beta` 等写法都能正确比较。

脚本抓取限制为 9 MB（与在线导入一致），失败不会影响已安装源，只在条目上显示错误信息。

## 二、音乐下载（边听边下 + 独立下载页）

### 使用方式

1. 首页侧边抽屉新增 **「下载」** 页（在「我的列表」和「设置」之间），进入后能看到所有任务、体积、速度与进度。
2. 下载页顶部可直接打开「边听边下」；打开后每次播放歌曲，播放地址解析完成即自动缓存整首，不影响播放。
3. 播放详情页（横屏/竖屏）的更多操作里新增 **下载按钮**，一键下载当前歌曲。
4. 歌曲右键菜单（搜索/歌单/我的列表）也新增「下载」，支持手动下载任意歌曲。
5. 下载页支持「全部 / 进行中 / 已结束」筛选、失败重试、单项删除、清空已结束（含删除文件）。
6. 「下载时保存歌词」默认开启，下载完成后会同时保存同名 `.lrc` 歌词文件（能获取到歌词时），有封面时还会保存同名 `.jpg`。

### 实现要点

| --- | --- |
| `src/core/download/index.ts` | 下载管理器：串行队列、地址解析、进度/速度计算、`.part` 临时文件、完成后移动为正式文件、歌词/封面旁文件、任务持久化与恢复 |
| `src/store/download/*` | 下载任务的状态、事件与 React Hook（`useDownloadList`） |
| `src/core/player/player.ts` | 播放地址解析成功后调用 `autoCacheMusic()`，复用刚拿到的 URL，避免重复请求 |
| `src/screens/Home/Views/Download` | 下载页：任务列表、筛选、进度条、重试/删除/清空、边听边下开关 |
| `src/config/constant.ts` | `NAV_MENUS` 增加 `nav_download`，抽屉与横屏侧栏自动出现入口 |
| `src/screens/PlayDetail/**/MoreBtn/DownloadBtn.tsx` | 播放页下载按钮（横屏/竖屏各一份） |
| `src/screens/.../settings/Download` | 「下载与缓存」设置页：开关、任务统计、保存目录、跳转下载页 |
| 列表菜单 | 在线列表与我的列表新增「下载」入口 |

### 设计取舍

- **顺序下载**：同一时间只跑一个任务，避免边听边下抢占播放带宽；手动任务会插到自动缓存任务前面。
- **保存目录**：默认使用系统公共音乐目录 **`/storage/emulated/0/Music`**（即安卓用户目录 Music），系统播放器与其他音乐 App 可直接扫描到；若应用无存储权限或该目录不可写，自动回退到 `<应用私有目录>/download`。手动发起下载时会尝试申请存储权限切换回公共目录。目录路径在设置页展示。
- **URL 复用**：边听边下直接复用播放器已解析的 URL；若下载时 URL 已过期导致失败，任务标记为失败，点「重试」会重新解析地址。
- **断点续传**：`react-native-fs` 的下载任务不支持可靠的断点续传，失败后会清理 `.part` 并从头开始，避免拼出损坏文件。
- **不支持的流**：检测到 `.m3u8` 地址会直接报错，不保存播放列表文件。
- **任务上限**：最多 300 条任务，超出提示先清理，避免 AsyncStorage 体积过大。
- **持久化节流**：进度刷新只更新内存状态，任务列表每 2 秒落盘一次，减少 IO。

## 三、配置备份与恢复（本地 + WebDAV，参考 MusicFree 的备份思路）

设置 → 备份与恢复 分为三个分组：**本地备份与恢复**、**WebDAV 备份与恢复**、**列表数据**（原有分组保留）。
前两者共用同一份备份内容和同一套恢复逻辑，只是存储介质不同。

### 备份内容

| 数据 | 说明 |
| --- | --- |
| 用户设置 | 全部 `AppSetting`（主题、播放、歌词、下载等所有设置项） |
| 自定义音源 | 音源列表 + **每个音源的完整脚本内容** + 来源地址与版本信息 |
| 歌单列表 | 默认列表、收藏列表、所有用户列表及其歌曲 |
| 不喜欢列表 | 不喜欢歌曲规则 |

### 使用方式：本地

1. **导出到本地**：选择保存目录，生成 `lx_config_日期_时间.json`（明文 JSON，与 WebDAV 备份完全同一种文件）。
2. **从本地恢复**：选择 `.json` 备份文件，确认后恢复。旧版生成的 `.lxmc`（gzip）文件仍可读取，方便升级后直接沿用。

### 使用方式：WebDAV

1. **WebDAV 设置**：填写服务器地址、用户名、密码、远程目录名（默认 `lx-music-backup`），可点「测试连接」验证。
   - 地址支持 HTTP/HTTPS，坚果云可直接填 `https://dav.jianguoyun.com/dav/`，缺少 `/dav` 前缀时会自动补全（坚果云密码需使用**应用密码**）。
   - 「测试连接」会完整走一遍 **MKCOL → PUT 探针 → GET 探针 → DELETE 探针 → PROPFIND**，可直接定位是上传还是下载环节不可用。
2. **上传到 WebDAV**：一键把当前配置以 `lx_config_日期_时间.json` 上传，目录不存在时自动 MKCOL 创建。
3. **从 WebDAV 恢复**：打开远程备份列表，按时间倒序列出所有备份（含大小与时间），可逐个「恢复」或「删除」，支持刷新。
4. 认证方式为 HTTP Basic（`Authorization: Basic ...`），兼容坚果云 / Nextcloud / ownCloud 等。

### 下载失败的兼容处理

恢复远程备份时下载失败的常见原因已逐项处理：

- 请求一律使用**标准大写 HTTP 方法**，并且**直接使用 `fetch`**，不再走应用内 `httpFetch`（避免被附加伪造的桌面浏览器 UA、以及响应被强制 JSON 解析）。
- URL 按**路径分段做百分号编码**，中文目录名、中文路径不会再导致请求被服务端拒绝。
- 下载优先使用 PROPFIND 返回的 `href` 还原出的**完整文件地址**；失败时再依次尝试「目录 + 编码文件名」「目录 + 原始文件名」。
- 上述请求全部失败时，自动改用**原生下载通道**（与音乐下载同一条 `react-native-fs` 通道，独立 OkHttp 客户端）重试一次。
- 错误信息里会带上服务端返回的原始内容（如 `HTTP 400 - xxx`，截断到 120 字），便于直接判断服务端拒绝原因。

两种方式恢复后的行为一致：

5. 恢复设置时与当前版本默认设置合并，旧备份不会缺失新增配置项；「是否同意用户协议」不会被覆盖。
6. 音源按原 id 恢复，恢复后 `common.apiSource` 仍指向原音源并立即重新加载；若音源缺失会自动回退到可用音源。
7. 列表恢复采用合并策略（与「导入列表」一致），不会删除备份之后新建的列表。

## 五、本地音乐扫描与播放（按文件夹管理，参考 MusicFree）

### 使用方式

1. 首页侧边抽屉新增 **「本地音乐」** 页（在「下载」与「设置」之间）。
2. 首次进入点右上角文件夹图标 → **添加目录**，选择要扫描的音乐目录（如 `/storage/emulated/0/Music`）。添加第一个目录后会自动开始扫描。
3. 顶栏按钮：**目录管理**（增删扫描目录）、**扫描 / 取消扫描**（扫描中显示进度条）、**清空**（仅清空扫描结果，不动磁盘文件）。
4. 两种视图：
   - **文件夹**：按歌曲所在目录分组，显示文件夹名、完整路径与歌曲数；点进去看该目录下的歌，支持「播放全部」。
   - **全部**：平铺所有扫描到的歌曲。
5. 搜索框可按歌名、歌手、专辑、文件名过滤，两种视图都生效。
6. 点歌曲直接播放（以当前列表为播放上下文，支持上下曲与循环模式）；右侧「⋮」菜单提供：播放、稍后播放、添加到我的列表、从扫描列表移除。
7. 设置 → **本地音乐**：短音频过滤开关 + 最小时长阈值（默认 60 秒），以及扫描概览与跳转入口。

### 实现要点

| 文件 | 说明 |
| --- | --- |
| `src/core/localMusic.ts` | 扫描核心：递归遍历目录、扩展名白名单、批量读元数据、短音频过滤、边扫边显示、取消扫描、按文件夹分组、播放 |
| `src/store/localMusic/*` | 扫描结果与扫描状态（state / action / event / hook） |
| `src/screens/Home/Views/Local/index.tsx` | 本地音乐页：文件夹 / 全部双视图、搜索、扫描进度、播放 |
| `src/screens/Home/Views/Local/MusicMenu.tsx` | 歌曲操作菜单（播放、稍后播放、添加、移除） |
| `src/screens/Home/Views/Local/ScanDirModal.tsx` | 扫描目录管理弹窗（复用 `ChoosePath` 选择目录） |
| `src/screens/.../Setting/settings/LocalMusic/index.tsx` | 设置页「本地音乐」分组 |
| `src/types/local_music.d.ts` | `LX.LocalMusic` 类型（持久化结构、文件夹分组、扫描进度） |
| `src/utils/data.ts` | `getLocalMusicData` / `saveLocalMusicData`（存储键 `@local_music`） |

要点：

- **复用上游已有的本地音乐基础设施**：`LX.Music.MusicInfoLocal` 类型与 `src/core/music/local.ts`（本地文件路径、内嵌封面、内嵌歌词的解析）本来就能处理 `source: 'local'` 的歌曲，所以扫描出来的歌可以直接播放、显示内嵌封面与歌词，也能走在线源兜底。
- 元数据读取失败（如 `m4a` 等原生模块不支持的格式）时**按文件名兜底**，仍能播放，不会因为读不出标签就丢歌。
- 递归扫描会跳过隐藏目录与 `Android`、`cache` 等系统目录，深度上限 12 层；扫描过程中每 5 个文件更新一次列表，边扫边显示。
- 扫描结果持久化在 `@local_music`，启动即显示上次结果，**不在启动时自动扫描**（避免拖慢启动和无端弹权限框）。
- 移除目录、移除歌曲、清空列表都只影响扫描结果，**不会删除磁盘文件**。
